# Home Assistant: что нужно на стороне HA

Панель — «тонкий клиент»: она рисует состояние сущностей HA и вызывает действия HA.
Часть логики живёт в самой панели (яркость по солнцу, возврат на главную,
настройки), часть — в HA (гашение экрана по движению, быстрый запуск музыки,
тренд температуры).

Все файлы в этой папке — в формате, который можно вставить в редактор HA
(**Настройки → Автоматизации и сцены → … → Редактировать в YAML**).
Идентификаторы сущностей в них — **мои**, замени на свои.

| Файл | Что это | Обязательно? |
|---|---|---|
| [`helpers.md`](helpers.md) | Таймер экрана, датчики тренда температуры | таймер — да, тренд — если нужна плашка «греется/остывает» |
| [`automation_screen_on.yaml`](automation_screen_on.yaml) | «Экран сарай ВКЛ»: будит экран по движению, запускает таймер | да, если нужно гашение по движению |
| [`automation_screen_off.yaml`](automation_screen_off.yaml) | «Экран сарай ВЫКЛ»: гасит экран по таймеру | да, в паре с предыдущей |
| [`script_music_quick_start.yaml`](script_music_quick_start.yaml) | Кнопки радио/плейлистов на экране «Музыка» | да, если используешь эти кнопки |

## 0. Разреши панели вызывать действия HA

**Настройки → Устройства и службы → ESPHome → (панель) → Настроить →
«Allow the device to perform Home Assistant actions»**.
Без этой галочки нажатия на панели молча не выполняются, а в логе HA пишется
`Service call ... rejected`.

## 1. Как узнать реальные id сущностей панели

HA строит id из **комнаты + имени устройства + имени сущности**. У меня панель
лежит в комнате «Сарай», поэтому настройка «Экран гаснет через» получила id
`number.sarai_panel_sarai_ekran_gasnet_cherez` (а не `number.panel_sarai_…`).
После первой прошивки открой устройство в HA и скопируй точные id — особенно
`number.…_ekran_gasnet_cherez` (его читают автоматизации гашения).

## 2. Гашение экрана: как это работает

```
движение / человек на камере ──► «Экран ВКЛ»  ──► light.turn_on подсветки
                                     │              (если кто-то дома)
                                     └─► timer.start (длительность = настройка
                                         панели «Экран гаснет через»)
timer.finished ──► «Экран ВЫКЛ» ──► кто-то всё ещё в кадре/датчик держит?
                                     ├─ да  → перезапустить таймер
                                     └─ нет → light.turn_off подсветки
```

* Касание тёмного экрана **не нажимает невидимые кнопки**: когда HA гасит
  подсветку, прошивка ставит LVGL на паузу; первое касание только будит экран.
  Включилась подсветка — «Экран ВКЛ» видит это и сам запускает таймер.
* Яркость при включении ставит **панель** (дневная или ночная из её настроек) —
  в автоматизации яркость не передаётся.
* В самой панели таймаут гашения библиотеки отключён (`Backlight timeout = -1`):
  экраном управляет только HA, иначе два таймера дерутся.

## 3. Музыка — как устроены кнопки быстрого запуска

```
кнопка на панели ──► script.sarai_muzyka_bystryi_zapusk  (preset: russkoe / avto / nravitsya / volna)
                         │  mode: single — повторные нажатия, пока музыка стартует, игнорируются
                         ├─ параллельно: ждём смены media_content_id у плеера (12 с)
                         └─ music_assistant.play_media (enqueue: replace)
                                 └─ если за 12 с трек не сменился → ещё одна попытка
```

* Плеер `media_player.sarai` — это **плеер Music Assistant** (в моём случае
  колонка на ESPHome, звук по протоколу Sendspin). Подойдёт любой плеер MA.
* Радио берётся либо из библиотеки MA (`library://radio/2`), либо прямой
  ссылкой на поток. Плейлисты — из библиотеки MA (`library://playlist/22` —
  «My Favorites» Яндекс Музыки, `library://playlist/21` — «My Wave»).
  Свои адреса узнай через **Инструменты разработчика → Действия →
  `music_assistant.get_library`** (`media_type: radio` / `playlist`).
* Зачем скрипт, а не прямой вызов с панели: при прямом вызове люди жмут
  кнопку повторно, команды накладываются, и MA отвечает
  `MediaNotFoundError` / `QueueEmpty`. «Моя волна» ещё и иногда возвращает
  пустую порцию треков (`There is nothing to play here`) — повтор это лечит.
* Панель в момент нажатия пишет «Запускаю…» и название пресета, пока из HA
  не придёт новый трек.
* Остальное (пауза, вперёд/назад, громкость) — обычные действия
  `media_player.*` прямо из прошивки; название трека, состояние и громкость
  панель читает из атрибутов плеера.

## 4. Тренд температуры (плашка «Парная: греется / остывает»)

Два хелпера из UI (см. [`helpers.md`](helpers.md)): **Statistics** «изменение за
2 минуты» и **Template**-сенсор `rising / falling / stable` с порогом ±0,3°.
Панель читает только итоговый сенсор `sensor.bania_temperatura_trend`.

## 5. Занятость бани/туалета

Панель ждёт **текстовые** сенсоры, значение которых начинается с «Занят…» или
«Свобод…» (у меня `sensor.zaniatost_bani_2`, `sensor.zaniatost_tualeta_2`).
Если у тебя бинарные датчики — сделай Template-сенсор, который превращает
`on/off` в «Занято/Свободно», или поменяй условие в прошивке
(`x.rfind("Занят", 0) == 0`).
